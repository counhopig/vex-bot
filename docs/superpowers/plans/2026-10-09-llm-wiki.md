# LLM Wiki Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give Vex a scheduled and on-demand LLM wiki that compiles the owner's Obsidian-vault notes into cross-linked `wiki/` pages, commits and pushes them, and can roll back an entire batch.

**Architecture:** A new `src/wiki/` subsystem owns a writable git clone of the vault. Only wiki runs — temporary agent runs with a restricted toolset (`vault_search`, `vault_read`, `wiki_write`, `wiki_edit`) — write `wiki/` and `raw/`. Every batch is one commit carrying `Vex-Batch`/`Vex-Kind`/`Vex-Scan-Base` trailers. A phased in-flight marker (`writing` → `committed` → `published`), per-path content fingerprints, and a history reconciler make every crash window recoverable. A bootstrap preview is reviewed before the first push. Owner-approved `bash`/MCP are outside the lock and are detected, not prevented.

**Tech Stack:** TypeScript ESM (NodeNext, strict), Node.js ≥24, `node:child_process` git, `better-sqlite3` is unrelated here, Vitest, Typebox config schema, Croner via the existing scheduler.

**Spec:** `docs/superpowers/specs/2026-10-09-llm-wiki-design.md`

## Global Constraints

- Only `<vault>/wiki/**` and `<vault>/raw/**` may be written automatically; every other vault path stays read-only.
- The only automatic vault writer is the wiki subsystem. General `write`/`edit` never write the vault; owner-approved `bash`/MCP/`delegate` are outside the lock.
- Never force push.
- One batch = one commit, with trailers `Vex-Batch: <uuid>`, `Vex-Kind: scheduled|bootstrap|on-demand`, `Vex-Scan-Base: <sha|none>`; rollback commits use `Vex-Rollback: <uuid>` + `Vex-Revert-Of: <batchId>` and no `Vex-Batch`.
- `advancesScan` is true for `scheduled`/`bootstrap`, false for `on-demand`.
- Relative TypeScript imports end in `.js`; Node built-ins use `node:`.
- Double quotes, two spaces, semicolons; `npm run lint` (tsc --noEmit) must stay clean.
- `.gitignore` already ignores `.worktrees/`; do not create worktrees in this plan.
- Keep `npm test` green at every commit; the existing 496 tests must not regress.

## Review Focus

The checks the spec implies that no single task's happy-path tests cover, most likely to bite first:

1. **Crash between git commit and marker update** — recovery must never restore files against a committed HEAD.
2. **Owner-approved `bash` edits the same `wiki/` file between two wiki writes** — compare-and-swap must abort, not overwrite.
3. **Remote diverged / force-pushed while a batch was pending** — rebase, incomparable cursor candidates, and "already pushed" checks.
4. **Path escape via symlinked subtree root or dangling symlink** — reject before writing.
5. **Bootstrap preview leakage and duplicate rollback** — no path may push an unpublished preview or revert twice.

Each line's test is added to the task that owns the code (marked `[Review Focus N]` below).
